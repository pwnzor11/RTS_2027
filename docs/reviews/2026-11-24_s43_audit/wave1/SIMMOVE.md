## Findings
### SIMMOVE-01 · HIGH · bug
What: A VEHICLE that surfaces from a tunnel network is handled twice. The tunnel code (TrySurface) puts a Unit telegraph on the exit cell and the vehicle in layer Surfacing, but RunTelegraphs (burrow code) also picks up every Unit telegraph whose subject is a Vehicle in layer Surfacing. It counts the telegraph down a second time and calls FinishSurfacing one tick early. FinishSurfacing then re-checks SurfaceCellOk, which needs soft land and no structure within SurfacingRing = 1. The tunnel exit cell is, by default, directly outside the entrance footprint (the test shows the exit (41,42) of a 2x2 hatch at (40,40)), so the check fails. The vehicle goes back to layer Burrowed with mission Surface, gets a second telegraph and appears at the nearest cell that does pass. The Occupancy claim that TrySurface made on the exit cell is never released.
Where: Simulation.Burrow.cs:28-37 (RunTelegraphs: only checks `g.Subject.Kind == Vehicle` and `VehicleLayer == Surfacing`, no check for a Transit entry; the Tunnels.cs:257-259 comment says it should leave transit telegraphs alone); Simulation.Tunnels.cs:300-325 (TrySurface, Occupancy.Claim at :316); Simulation.BurrowMove.cs:249-264 (FinishSurfacing fallback sets layer Burrowed, never calls Occupancy.Release) and :223-241 (BeginSurfacing moves Position, no Release).
Evidence: read — trace: TrySurface sets telegraph = T and claims the cell. In the same tick RunBurrowing decrements it to T-1. Every later tick AdvanceTunnelTransit sets it to t.TicksLeft, then RunTelegraphs subtracts 1 more, so it reaches 0 one tick before the transit entry does. FinishSurfacing runs with SurfaceCellOk -> DiveCellOk -> !StructureNear(exit,1), which is false next to the entrance. Occupancy.Release only clears the cell that matches the CURRENT Position (Occupancy.cs Release), so the old exit cell keeps `VehicleAt = this vehicle` after the vehicle surfaces elsewhere. Infantry are not affected (RunTelegraphs only looks at vehicle subjects), and the only full-cycle tunnel test (TunnelTransitTests.cs:217) uses an infantry unit. The vehicle tests (:128, :148) stop at the first Surfacing.
Impact: Directorate crawlers and other M/L-size tunnel vehicles never leave the network at the exit. They arrive a few cells away after an extra 60-tick telegraph, hidden underground (Burrowed) meanwhile. Each trip can leave a phantom vehicle occupant on the exit cell (blocks vehicles and infantry there and in FindFreeExitCell for the rest of the match). Repeated use fills the ring around an entrance with phantoms.
Fix idea: in RunTelegraphs skip telegraphs whose subject has a Tunnels.Transit entry (as the comment says), and release the claim in FinishSurfacing's fallback.   Changes a match outcome / number / visible text?: yes (tunnel arrival timing and place for vehicles; hashes move)

### SIMMOVE-02 · MED · bug
What: A unit underground whose destination exit has no free cell within ring 8 waits there with no limit, still counting against the owner's network cap. Player orders cannot reach it (PinUnderground undoes them), so the unit cannot be rescued. Every other entrance's queue of that owner stalls as the cap fills.
Where: Simulation.Tunnels.cs:232-236 (`if (t.TicksLeft == 0 && TrySurface(...))`, retried every tick forever), :445-458 (NetworkPoints counts Tunnel layer); Production.cs:467-494 (FindFreeExitCell, MaxExitSearchRing = 8). ActorStandsOn (Production.cs:496) also counts air units hovering over a cell and other underground/burrowed actors.
Evidence: read — the comment "ASSUMED (M3-02): ... waits underground ... retries every tick" shows the design never gives up. The cap check `NetworkPoints(owner) + points > cap` is in StartTunnelDraws (:268).
Impact: A walled-in or enemy-camped exit (an exit inside a sealed base, a Hatch inside a pocket of walls) turns up to 10 network points into a permanent traffic jam; those units are lost to the player. A retry costs up to 289 cells x every unit and infantry slot (ActorStandsOn) per tick per stuck unit.
Fix idea: after N failed ticks re-route the unit (RerouteTransit) to another entrance or surface it at the nearest passable cell, and make ActorStandsOn skip air units.   Changes a match outcome / number / visible text?: yes (edge cases only)

### SIMMOVE-03 · LOW · bug
What: Radiation damages garrisoned soldiers. RunRadiation skips only IsUnderground (Tunnel, Burrowed, Surfacing, Passenger), and Garrisoned is not in that set. RunAshfall (same package) explicitly skips both underground and carried.
Where: Simulation.Ground.cs:85 versus Simulation.Ashfall.cs:23 and :58; Core/ActorLayers.cs:9-15.
Evidence: read — the comment at Ground.cs:84 says "underground actors (tunnel, burrowed, passenger) take no radiation damage"; IsUntargetableBy at :366 lists Garrisoned separately because IsUnderground leaves it out.
Impact: Infantry in a garrisoned building on a contaminated cell take radiation damage. Passengers in a transport and soldiers in a tunnel do not.
Fix idea: skip `ActorLayers.IsCarried` in RunRadiation too (or note the decision that garrisons are not shielded).   Changes a match outcome / number / visible text?: yes (small)

## Suspects (unproven)
- Path budget (s18 #5): the fix is present (M13-05, D-205: blocked or enclosed goals are retargeted to the nearest reachable cell via region labels, and new requests are held back once a call has charged more than BurstFactor(4) x 4000 expansions). Still, `Process` always solves EVERY request that has already waited, with no cap (PathService.cs Process, the `while (_queue[k].Waited)` loop). A burst of N long-range requests that arrive in a heavily overdrawn tick is therefore solved in one frame. Each solve is bounded by the map size, but N is not. Proof needed: a profile with ~100 queued 200-cell requests on the largest map.
- Carrier hangar links use slot INDEX only (`_naval.HangarOf[j] == carrier`, Carrier.cs). If a carrier ever leaves through a quiet removal (RemoveMobileQuietly does not call OnCarrierDying) and its slot is reused by another own carrier in the same tick, docked aircraft would silently attach to the new ship. No such path found for carriers today (the quiet removals are Kite, Raid one-use, hangar aircraft).
- Simulation.Rigs.cs ApplyPack (unpack branch) does not check the rig's layer. A packed rig riding in a transport can be told to unpack. SyncPassengers/ParkVehiclePassenger resets its mission to Sleep the same tick, and RunRigs then aborts the unpack, so it looks harmless. Needs a test to be sure no building is placed.
- SyncPassengers (Transport.cs:90) drops an infantry passenger whose carrier is gone onto the surface WITHOUT claiming a cell (SlotCell is stale, no map slot set). The comment says it cannot happen because OnTransportDying removes passengers first; I found no path where it can, but if it ever does the soldier is invisible to occupancy.
- Missions/MoveMission.cs (761 lines) was not read; the new StuckLadder (S41) looks sound by itself (Replan 60 / Sidestep 120 / Relax 200 / Abandon 320 ticks).

## Checked and fine
- Passengers lost when a container dies: transport death goes through RunCleanup -> OnM3MobileDying -> OnTransportDying (infantry and vehicle passengers removed quietly, nested APC soldiers too); carrier death -> OnCarrierDying (docked lost, airborne orphaned); garrison removal handled elsewhere. Deploy/pack/tender-dock removals (RemoveVehicleForDeploy, RunTenders) never carry passengers (transports with passengers route Deploy to unload).
- Passengers that keep acting: Apply() drops unit orders to carried units (IsOrderToCarriedUnit, s18 #4 is fixed); SyncPassengers/ParkVehiclePassenger reset missions every tick; RunCarriers/RideAndRepair for docked aircraft; combat skips underground and passenger actors (Combat.cs:242,249); splash spares riders (Combat.cs:401).
- Tunnel queue/transit consistency: Validate* passes run before Advance, so QueueIndexOf is never -1 there; re-route when the destination is lost, kill-with-no-entrance is the documented D2 decision (test ExitLost_WithNoSurvivingEntrance...).
- Impassable placement: FindUnloadCell/FindVehicleLandCell/FindFreeExitCell/FindScatterCell/Spread all go through TerrainOk or IsPassableTerrain; ships' vehicle cargo needs a `landing` cell; landing craft refuse non-standable shore cells.
- Out-of-bounds: MapState.Idx and GroundState.IndexOf are unchecked, but every caller I traced (StructureNear, DiveCellOk, SurfaceCellOk, HatchSiteOk, FindUnloadCell, Spiral users, Landing, Beachhead RecomputeBeachhead clamps, CheckBeachheadAndWater after the footprint check) tests InMap or Contains first; PathService has InMap guards and a checked Factor().
- A* budget: group search is a backward A* that stops when all starts are settled; GroupWalk terminates (g strictly falls) and cannot index -1; single search is cached and the cache key includes passer and map version.
- Beachhead mask is rebuilt on place, remove and capture; bootstrap when the player owns no building; Occupancy claim/release by id.
